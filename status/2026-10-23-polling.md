# Cached polling optimization — 23 October 2026

## Change
v0.0.13.4 shares one property/query2 output snapshot across light, cover and switch polls for up to five seconds. Device-level identities, brightness/colour commands, cover position/tilt and availability reconciliation stay intact. Commands serialize with snapshot reads and invalidate their cache even after uncertain failures.

Consumption-only meters share one metering/getLatest snapshot per series, preserving Ws units, meter identity, real zero and unknown readings. Producer-enabled meters retain their previous API paths.

Shared reads have a five-second timeout and briefly share failures so a disconnected server does not receive one retry per entity. A later cycle retries automatically.

## Traffic audit
The previous v0.0.13.3 already reads output target values from the server property cache and receives device sensors through events. The reviewed polling paths do not repeatedly invoke device/getSensorValue or device/getOutputValue. Firmware checks remain every six hours.

This is an HTTP-request/load optimization, not evidence of a physical bus-traffic reduction. No aggressive per-device bus polling was found to remove from this installation.
